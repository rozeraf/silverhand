# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Johnny Silverhand: The Engram** — a non-commercial fan tribute single-page site (Cyberpunk 2077). React 19 + Vite 7 + TypeScript, package manager **Bun**. UI copy is mixed Russian/English; README and `todo.md` are in Russian.

## Commands

```bash
bun install --frozen-lockfile   # install exactly what bun.lock pins (same as CI)
bun dev                         # dev server
bunx tsc --noEmit               # typecheck (no script for it yet)
bun run build                   # production build → dist/
bun run preview                 # serve dist/ locally
bun run changelog -- --tag vX.Y.Z   # regenerate CHANGELOG.md for an upcoming release
bun run release-notes           # release notes for the latest tag
```

There are no tests and no linter. "Verified" means `bunx tsc --noEmit` and `bun run build` both pass; for UI/terminal behavior, also check it in `bun dev`.

## Git workflow (follow strictly)

- **`dev`** is the working branch. Do work on `dev` or on short-lived `fix/*` / `feat/*` branches cut from `dev`.
- **`main`** only receives changes through a pull request `dev → main`. Never commit or push to `main` directly.
- **Releases** are annotated tags `vX.Y.Z` on `main`, and pushing the tag is the only trigger. `.github/workflows/pages-deployment.yaml` ("Release") builds with Bun, deploys `dist/` to Cloudflare Pages, then creates the GitHub Release with notes from git-cliff. Never create the Release by hand. A plain push to `dev`/`main` deploys nothing.
- **Changelog**: `CHANGELOG.md` is generated by git-cliff (`cliff.toml`) and is never hand-edited. Before tagging, run `bun run changelog -- --tag vX.Y.Z` on `dev` and commit it as `chore(release): vX.Y.Z`; it reaches `main` with the release PR. `bun run release-notes` prints the notes for the latest tag. Non-conventional and merge commits are excluded, so commit messages must follow the format.
- Versioning is SemVer: `fix` → patch, `feat` → minor, breaking (`!` / `BREAKING CHANGE`) → major.
- Keep `dev` a fast-forward ancestor of `main` after each release (`git merge --ff-only main` on `dev`).
- When resolving a merge conflict, never take one side wholesale. Merge `680da22` did that and silently reverted all of `dev`; `2d97f73` had to restore it.
- `bun.lock` is committed and must be updated together with `package.json`, because CI installs with `--frozen-lockfile`.
- Commit style: Conventional Commits with scopes, e.g. `fix(terminal): …`, `feat(player): …`, `docs: …`. Types map to changelog sections: feat, fix, perf, refactor, style, docs, ci/build, chore.
- `todo.md` is the live backlog. Tick items there when a change completes them.

## Architecture notes (non-obvious parts)

- **Styling is split in two.**
  - `styles/main.css` (imported in `index.tsx`) holds the design tokens and every signature piece: `.display`, `.label`, `.outline-text`, `.btn*`, `.nav*`, `.hero*`, `.glitch`, `.marquee`, `.paper`, `.evidence`, `.rubber-stamp`, `.redact`, `.hazard`, `.blueprint`, `.spec`, `.relic-frame`, `.vinyl`, `.seek`, `.switch`, the CRT classes and all keyframes.
  - Tailwind v4 is built locally through `@tailwindcss/vite` (no CDN) and is used for layout/spacing only. `main.css` starts with `@import "tailwindcss"` and an `@theme` block that maps the tokens to utilities: colors `ink`, `coal`, `line`, `bone`, `dust`, `blood`, `acid`, `relic` (plus legacy `cp-*`), fonts `font-display`/`font-cyber` (Oswald), `font-sans` (Golos Text), `font-mono` (JetBrains Mono).
  - Order is fixed by cascade layers: everything of ours sits in `@layer components`, so a Tailwind utility on an element always beats a component class (`hidden` beats `.icon-btn`'s `display`). Keep new component CSS inside that layer. Before this, dev and production disagreed on that order.
  - Class names must appear as whole strings in the source: Tailwind scans files, so `"text-" + color` produces no CSS.
- **Design direction** — a punk zine about a dead rocker, read through a failing biochip. Keep to it when adding UI:
  - red (`blood`) leads; bone "paper" sections (`.paper`, `.dossier-sheet`) break up the dark ones; yellow (`acid`) is for hazard tape, highlights and Johnny's marker on dark sections; cyan (`relic`) is only for the rare "Relic malfunction" glitch. The Relic section is red, like the chip in the source art, and shows `relic.webp` unfiltered;
  - poster-size Oswald headings (`.display`), mono `.label`/`.section-index` captions, sections opened with `SectionHead` (index like `A1`, kicker, title);
  - two voices: the official corporate record, and Johnny's red marker over it — `.scrawl` notes (Caveat), `.struck` and `.circled` words. Keep his remarks short, sarcastic and in character; don't put lore facts only in them;
  - paper ends in a torn edge (`.tear`), and the `.relic-fx` layer (shown with film grain) flashes a brief "Relic malfunction" screen tear about every 30 s;
  - `Navbar` underlines the current section and its bottom line is the scroll playback head;
  - motion borrowed from fan edits: `Kinetic` lands the words of a big statement one by one on scroll (use it for poster-size quotes only), `.smear-cut` replays a short tear when the view switches, cut-out PNGs get a hard yellow "sticker" offset on hover (`.blueprint--cutout`);
  - fonts must support Cyrillic (the old Orbitron/Rajdhani did not) and are self-hosted: `@fontsource/*` packages imported in `index.tsx`, never a font CDN — when Google Fonts failed to load, the whole layout fell apart;
  - animate only `transform`/`opacity`, and add new animations to the `prefers-reduced-motion` block at the end of `main.css`.
- **`App.tsx` orchestrates the page.** Overlays are `Terminal`, `SettingsModal` and the full-screen `Samurai` player. Content sections and `Footer` are `lazy()`-loaded.
- **The site has two views.** By default it is the official record. Logging in as Silverhand in the terminal (`localStorage.classified === "true"`) switches to "Johnny's view":
  - `App` sets `<html data-view="johnny|official">`; CSS in `main.css` ("Two views") shows `.scrawl` notes, `.struck`/`.circled` marks and `.johnny-only` elements only in Johnny's view, and hides `.official-only` there. Add new marker notes with those classes; no React state is needed;
  - `ClassifiedSection` ("what really happened in the tower") renders only in Johnny's view, and `Navbar` gets `johnnyView` for its badge;
  - `logout` in the terminal returns to the official view.
- **`ClassifiedSection` is the factual account** of the 2023 raid from the tabletop canon (R. Talsorian's Cyberpunk books), set against what the engram remembers in the game.  It opens with Alt Cunningham's in-game lines about the engram (verbatim English from Cyberpunk 2077, confirmed by the project owner from game screenshots; the Russian is our translation) — keep the English wording exact. Johnny's `.scrawl` lines argue with it. Where sources disagree (casualties, who set off the bomb) the text says so; keep it that way and check lore claims before adding any.
- **`context/PlayerContext.tsx`** owns the single `Audio` element, the `TRACKS` list and playback state, so music keeps playing when the `Samurai` screen closes; `Navbar` shows a mini-player once something was started. Progress ticks live in a separate context (`usePlayerProgress`) so only the player screen re-renders on them. Nothing is fetched until the listener presses play.
- **`context/SettingsContext.tsx`** keeps the settings in `localStorage.cyber_settings`. When `bootSequence` is on (the default), the terminal with its boot animation opens on every page load. Legacy key `has_visited` is read once for migration and then removed. `enableAnimations` controls only the `RevealOnScroll` fade-ins.
- **CRT has two tiers.**
  - `enableScanlines` ("CRT DISPLAY") renders `CrtOverlay.tsx`, the lite mode: one static phosphor/vignette layer plus scanline-flicker and rolling-band layers that animate only `opacity`/`transform` (`.crt-lite*` in `index.html`). It is cheap and touches neither scrolling nor the cursor.
  - `enableCrtWarp` (Experimental, only with CRT on) switches to `CrtShader.tsx`: a full-screen WebGL pass plus the `.crt-barrel-surface` SVG displacement filter over the whole page, inside an internal scroll container. The filter re-rasterizes the DOM on every scroll or animation, so this mode is extremely heavy (≈15× fewer frames than lite in a headless benchmark).
  - Use the derived `crtWarp` from `useSettings()` for "heavy mode active" checks. Components that degrade effects (the Engram tilt) and the forced/warped `CustomCursor` key off `crtWarp`, not `enableScanlines`. `CustomCursor` warps its position to match the barrel geometry, so change those together.
- **Media goes through `assets.ts`.** Files in `assets/` and `music/` are pulled in with eager `import.meta.glob(..., { query: "?url" })`, so Vite hashes them and **every MP3 ships in `dist/`** (~27 MB of the ~33 MB build). Always reference media via `ASSETS`, never via hard-coded paths. Moving music out to Cloudflare R2 is planned in `todo.md`.
- **Terminal** (`components/Terminal.tsx` + `terminal/`):
  - Client-side virtual filesystem, built by `terminal/filesystem.ts` from `import.meta.glob` over `terminal/files/**/*.txt`, `assets/` and `music/` (media appears under `/srv/silverhand`).
  - To add a document, drop a `.txt` into `terminal/files/`. Special owner/group/mode/size goes in `terminal/metadata.ts`. Users live in `terminal/users.ts`.
  - `.txt` is hidden in virtual paths, except for the puzzle files `target.txt` / `incident.txt`.
  - POSIX-style `rwx` checks really apply to commands. VFS changes last only for the session. Auth state lives in `localStorage` (`username`, `authenticated`, `classified`).
  - Boot/close timers go through the `schedule()` helper, which clears them on close/unmount. Use it instead of a raw `setTimeout`.
  - `index.tsx` runs in `React.StrictMode`, so effects must clean up after themselves.
- **The login puzzle is part of the experience.** Do not reveal the passphrase (`SECRET_PASS`) or the solution in docs, README, commit messages or UI copy.
